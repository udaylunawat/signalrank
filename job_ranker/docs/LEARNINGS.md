## Environment & Running

### Correct run command
Do NOT use `uv run python -m job_ranker.batch.run` — that module has no `__main__` block and exits silently with code 0.

Use the entrypoint:
```bash
# Interactive (prompts for missing args)
.venv/bin/python -m job_ranker.entrypoint run --user example

# Force-refresh with default search query
.venv/bin/python -m job_ranker.entrypoint run \
    --user example \
    --search "ai platform engineer|ml platform engineer|mlops|llmops|genai|agentic systems|ai infrastructure|forward deployed engineer|developer productivity engineer" \
    --hours-old 72 \
    --force-refresh \
    --skip-enrich
```

Or via just:
```bash
just run-refresh   # force-refresh with preset search query
just run-example      # interactive prompts
```

### VIRTUAL_ENV conflict
If shell has `VIRTUAL_ENV` pointing to a different Python (e.g. Python 3.14 homebrew),
`uv run` warns but proceeds. However, packages added via `uv add` may land in the wrong
environment. Always use `.venv/bin/python` directly to be safe:
```bash
.venv/bin/python -m job_ranker.entrypoint run ...
```

### JobSpy dependency
The project requires the **speedyapply fork** of JobSpy (not the PyPI `jobspy` package).
- PyPI `jobspy==0.31.0` installs as `jobs.py` — `from jobspy import scrape_jobs` fails.
- Correct install:
  ```bash
  .venv/bin/python -m pip install git+https://github.com/speedyapply/JobSpy.git
  # or via uv:
  uv pip install git+https://github.com/speedyapply/JobSpy.git
  ```
- pyproject.toml has this commented out — remember to install it manually after `just install`.

## Package Layout

The project is a pip-editable install. There are **two copies** of the app code:
- `job_ranker/app/` — source files (edit these)
- `job_ranker/job_ranker/app/` — installed package (auto-generated by editable install)

When Streamlit runs, it imports from the installed path (`job_ranker/job_ranker/...`),
not from the source path directly. Changes to source files are reflected immediately
due to the editable install.

## DuckDB

### File location
The database is a single file at `job_ranker/duckdb` (no `.duckdb` extension, not in a subdirectory).

### Path resolution in db.py
- Source `app/db.py`: `Path(__file__).resolve().parents[1] / "duckdb"` → `job_ranker/duckdb` ✓
- Installed `job_ranker/app/db.py`: needs `parents[2]` (extra level for installed path) → `job_ranker/duckdb` ✓

The installed copy must use `parents[2]` because `__file__` resolves to
`job_ranker/job_ranker/app/db.py` (one level deeper than source).

### Read-only for UI
UI connects with `read_only=True`. Only the batch writer opens it in read-write mode.
One batch run may write at a time.

## Batch Pipeline Stages

1. **Scrape** — JobSpy + LinkedIn RapidAPI + Gmail alerts → raw jobs DataFrame
2. **Ingest** — upsert into `jobs_raw` table in DuckDB
3. **Enrich** — fetch missing LinkedIn descriptions (skip with `--skip-enrich` to avoid 429s)
4. **Skills** — `populate_missing_skills` (embedding-based)
5. **Rank** — semantic similarity + signals → A-F grades, persisted to DB

The `--skip-enrich` flag is safe for most runs and avoids LinkedIn rate limits.

## Ranking System (v3)

- **Grades**: A–F
- **QA blocklist**: filters junk before scoring
- **Semantic floor**: 0.65 similarity minimum
- **Hidden gem bonus**: boosts underrated roles
- **Contract detection**: penalizes contract jobs
- **Tier expansion**: 20+ tiered companies
- **Fuzzy seniority dedup**: removes near-duplicate titles at same company
